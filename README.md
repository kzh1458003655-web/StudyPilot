# 知序 StudyPilot

基于本地大语言模型与 RAG 的多场景智能备考系统。

StudyPilot 面向课程考试、考研、笔试和面试等以文本资料为主的备考场景。系统以“项目”作为数据边界，将资料理解、知识问答、真题分析、模拟训练和学习诊断连接成一个完整闭环。

> 课程版原型已归档。当前分支已完成目标架构、三个业务模块、系统级验证与最终交付文档。

## 产品闭环

```text
创建备考项目
  → 上传教材、讲义、知识点、历年真题和参考答案
  → 构建项目知识库
  → 基于资料进行溯源问答
  → 分析历年真题的知识点考查频次
  → 生成全新的模拟试卷
  → 在线作答
  → 自动测评
  → 诊断薄弱知识点
  → 推荐巩固练习或生成短期复习建议
```

## 核心模块

### 1. 资料知识库与溯源问答

- 上传、查看、删除和处理文字型 PDF；
- 支持教材、讲义、知识点、历年真题和参考答案等资料类型；
- 对知识资料进行文字提取、分页、分块和 BM25 等检索索引构建；
- 回答展示真实资料名称、页码和原文片段；
- 检索不到充分依据时明确说明资料不足，不编造答案或来源；
- 保存对话、消息和引用快照，资料删除后历史记录仍可读。

知识问答只读取当前项目内可用的知识资料，不直接使用历年真题作为问答依据。

### 2. 真题知识点分析与模拟题生成

- 对文字层完整的历年真题进行临时题目划分；
- 从不同原始题型中提取并归一化知识点；
- 统计知识点考查频次、累计分值和历年变化；
- 根据统计结果形成组卷方案，再从知识资料中检索出题依据；
- 只生成单项选择题和简答题，并进行题数、字段、答案、来源、重复度和知识点覆盖校验；
- 生成全新的模拟题，不直接改写或复用历年原题。

真题分析关注知识点分布，不建设可直接作答的原题题库，也不承诺预测真实考试题目。

### 3. 智能测评与薄弱点诊断

- 支持模拟试卷在线作答和历史作答记录；
- 单项选择题由程序按照标准答案确定性判分；
- 简答题先按服务端评分要点给出稳定反馈，完整架构中可再接入本地模型辅助评分；
- 保存评分依据、答案解析、错题和测评报告；
- 根据知识点、题目难度和近期错误情况计算掌握度；
- 输出薄弱知识点、针对性练习和短期复习建议。

原有复习计划能力并入测评与诊断模块，不再作为独立的核心产品模块，但已有的计划生成、时间约束、事务保存和版本记录可以作为技术成果继续保留。

## 已确定的产品边界

- 项目是最高层业务边界。资料、对话、引用、试卷、作答和报告都必须绑定项目，项目之间严格隔离。
- 课程可归档和恢复；归档会隐藏课程入口，但会保留课程内的资料、问答、模拟考和测评记录。
- 资料删除只影响后续使用，不破坏已经生成的问答引用、试卷快照和历史测评；删除整个项目时按项目规则全部清理。
- 目前只处理能够直接提取文字的 PDF，不增加 OCR、图像识别或多模态理解能力。
- 真题中的其他文本题型可以参与知识点分析；系统最终生成、作答和测评的题型仅限单项选择题与简答题。
- 模拟考不是预测系统。历年真题用于分析题型、难度、频率和知识点分布，不承诺命中原题。
- 系统按本地个人使用场景设计，当前不包含登录、注册、角色权限和多用户账号体系。
- Agent 不是强制目标。资料问答、真题分析和模拟测评优先采用可验证的固定智能工作流；只有模型自主选择工具并根据中间结果调整步骤时才称为 Agent。

## 总体架构

```mermaid
flowchart LR
    USER[用户] --> FE[Vue 前端]
    FE --> API[Spring Boot REST / SSE]

    subgraph JAVA[Java 模块化单体]
        API --> DOC[资料中心]
        API --> QA[溯源问答]
        API --> EXAM[真题分析与组卷]
        API --> ASSESS[测评与诊断]
        QA --> RETRIEVAL[RetrievalGateway]
        EXAM --> RETRIEVAL
        ASSESS --> RETRIEVAL
        QA --> MODEL[ModelGateway]
        EXAM --> MODEL
        ASSESS --> MODEL
    end

    DOC --> DB[(PostgreSQL / Supabase)]
    QA --> DB
    EXAM --> DB
    ASSESS --> DB
    RETRIEVAL --> CPP[C++ 检索服务]
    MODEL --> LLM[llama.cpp 本地模型]
```

### 目标架构基线

| 层次 | 目标方案 |
| --- | --- |
| 前端 | Vue 3、TypeScript、Vite、Vue Router、Pinia、shadcn-vue、Tailwind CSS |
| 后端 | Java 21、Spring Boot 3.5、Spring MVC、Bean Validation、Spring JDBC |
| 后端组织 | 单个 Spring Boot 模块化单体，按 `document`、`qa`、`exam`、`assessment` 等业务能力划分 |
| 数据库 | Supabase 托管 PostgreSQL，通过 JDBC 访问 |
| 检索 | 独立 C++ 检索服务，后端通过 `RetrievalGateway` 调用 |
| 模型 | 独立本地模型服务，后端通过 `ModelGateway` 调用 llama.cpp |
| 文档处理 | Apache PDFBox，暂不处理扫描件 |
| 测试 | JUnit 5、Mockito、Vitest、Vue Test Utils、MSW、Playwright |

后端业务模块只依赖 Gateway 接口，不直接管理 C++ 服务、模型进程或端口。跨模块读取通过公开的查询 Service 或只读 DTO 完成，禁止直接访问其他模块的 Repository。

前端采用 `app / modules / shared` 三层结构：业务模块拥有自己的 API、页面、组件、状态和校验；外部 DTO 必须经过运行时 Schema 校验和 mapper 转换后才能进入内部模型；普通 HTTP 请求统一经过 Axios 实例。

## 模型评测结论

当前最新的两模型专项评测将 **Qwen3-4B Q4_K_M** 作为课程资料问答的候选默认模型：15/15 请求完成，资料依据与结构化输出更稳定，JSON 解析通过率为 3/3，平均首 token 时间约 0.080 秒，平均生成速度约 58.47 token/s。

更早的多任务 Benchmark 中，Qwen3.5-4B 综合分略高于 Qwen3-4B；因此最终模型仍应根据资料问答、出题结构、简答题评分和实际演示场景综合确认。评测数据与原始证据见：

- `tests/model-evaluation/模型选型实测报告.md`
- `tests/model-evaluation/summary.json`
- `tests/model-benchmark/README.md`

## 推荐演示流程

1. 创建一个备考项目并上传教材、知识点、历年真题和参考答案。
2. 等待资料处理完成，查看资料类型和处理状态。
3. 对项目知识资料提问，查看回答、资料名称、页码和引用片段。
4. 临时划分可解析的真题文本题目，提取并归一化知识点。
5. 展示知识点考查频次、累计分值和历年变化。
6. 根据统计结果和知识资料生成只包含单项选择题与简答题的模拟试卷。
7. 在线完成模拟试卷并提交。
8. 查看客观题判分、简答题辅助评分、答案解析、错题和薄弱知识点。
9. 推荐下一组巩固练习或生成短期复习建议。

当前目标版本可演示资料上传、溯源问答、真题分析、模拟组卷、在线作答与测评。系统级验证与最终部署说明见 `docs/产品相关/系统验证记录.md`。

## 开发原则

- 当前先完成 Harness 和架构重构，架构基础链路验证前不开始产品任务。
- 先确认产品边界，再实现页面、接口和数据结构。
- 按业务模块分工，每个模块对自己的前后端、数据库、算法、模型调用和测试负责。
- 保持项目、资料、对话、试卷、作答和报告的归属清晰，任何查询都必须带有明确的业务边界。
- 优先使用固定、可验证、可测试的智能工作流，不为技术名词强行引入 Agent。
- 结构化模型输出必须经过程序解析和规则校验，校验失败不得静默保存。
- 修改公共契约前检查全部调用方，并同步更新相关文档和测试。
