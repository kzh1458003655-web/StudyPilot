## 模块协作架构

课程、PDF、模型服务和数据库作为公共基础，三名成员分别负责一条完整的前后端业务链路。

```mermaid
flowchart LR
    PDF[课程资料与历年试题 PDF]

    subgraph M1[模块一：资料智能问答]
        QF[聊天与引用页面]
        QB[问答、会话与 RAG 接口]
        QD[(会话、消息、引用)]
    end

    subgraph M2[模块二：考频统计与模拟出题]
        EF[考频图表与模拟试卷页面]
        EB[课程题库、知识点统计、组卷接口]
        ED[(试题、知识点、模拟题)]
    end

    subgraph M3[模块三：答题与智能评测]
        AF[答题与逐题反馈页面]
        AB[交卷、客观题判分、简答题评分点反馈]
        AD[(作答、得分、评分点、薄弱项)]
    end

    INFRA[C++ 本地推理基础设施\n索引 / 队列 / 取消 / 指标]
    LLM[Qwen3-4B 本地模型]

    PDF --> M1
    PDF --> M2
    M1 --> INFRA
    M2 --> INFRA
    M2 -->|模拟试卷与评分点| M3
    M3 --> INFRA
    M3 -->|薄弱知识点继续提问| M1
    INFRA --> LLM
```

三个目标模块共用以下约定：

- 所有文档、试题、会话、练习和评测记录都绑定课程编号。
- 前端统一调用 Spring Boot，避免直接访问本地模型。
- Java 负责业务规则、数据库事务和数据校验，C++ 负责检索、推理队列及运行指标。
- 模拟试卷在 Java 服务端关联题目；参考答案和评分点只在服务端保存，不传给浏览器。
- 客观题由 Java 确定性判分；简答题先按评分点给出稳定反馈，后续可接入本地模型生成更丰富的讲解。
- 当前提供一套数据库基础演示题库，用于离线体验完整流程；实际课程可由资料整理环节写入课程专属题库。
