# 仓库组织预期

## 当前阶段

Agent Harness 和配套说明已于 2026-09-08 建设并验证完成，本阶段没有执行架构重构或产品功能开发。下一位 Agent 根据 [Harness](../harness/README.md) 从 `ARCH-001` 开始。

## 目标组织

仓库根目录按前端、后端和 C++ 三个技术边界组织代码，同时保留文档、公共约束、脚本和验证入口：

```text
StudyPilot/
├── frontend/             # Vue 前端
├── backend/              # Spring Boot 后端
├── ai/                   # C++ 检索和本地模型基础设施
├── docs/
│   ├── 产品相关/         # 产品定位、需求和仓库组织
│   ├── harness/          # Agent 状态、进度、验证和交接
│   └── 关键记录/         # 架构、数据库、接口和 ADR
├── scripts/              # 安装、初始化、构建和验证脚本
├── tests/                # 跨模块集成和系统证据
└── README.md
```

前端、后端和 C++ 服务共享的数据结构、字段和协议约束必须有单一事实来源。当前统一记录在 [关键记录](../关键记录/README.md)；后续若需要生成可执行 Schema 或客户端代码，应先通过 ADR 确定其仓库位置，不能在三个技术目录中分别维护不同版本。

## 文档约束

- 产品事实放在本目录；
- 前后端内部架构分别由各自架构文档负责；
- 跨模块设计和关键决策放在 `docs/关键记录/`；
- 执行进度和交接放在 `docs/harness/`；
- 名称含 `-旧` 的文档冻结，只读，不再更新。
