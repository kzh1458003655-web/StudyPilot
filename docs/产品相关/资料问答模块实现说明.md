# 资料知识库与溯源问答模块实现说明

## 这部分完成了什么

用户先创建学习项目，再上传一份可直接提取文字的 PDF。后端将文件写入默认的 `D:\大四课程设计\StudyPilot-runtime\uploads\<项目编号>`，计算 SHA-256，按页提取文字并分块，然后把页面内容交给 C++ 服务建立检索索引。只有 C++ 返回索引成功后，资料状态才会变为 `READY`，因此问答不会读取半成品。

问答页面只请求当前项目编号。Java 后端从 PostgreSQL 查询本项目处于 `READY` 状态的教材、讲义和知识点资料；历年真题、参考答案不会进入问答范围。检索请求包含这一批资料的索引 ID。即使 C++ 服务意外返回其他资料的片段，Java 还会再做一次索引 ID 白名单过滤。

模型只接收过滤后的原文片段。页面显示的资料名、页码和摘录由检索快照生成，并不相信模型自行输出的来源。没有可用资料或没有检索命中时，系统保存本次提问和“资料不足”的回答，但不调用模型生成确定性结论。

## 数据流

```text
Vue 项目页
  ├─ POST /projects              → 创建项目
  ├─ POST /documents             → PDF 保存、解析、分块、C++ 建索引
  └─ POST /qa                    → 资料范围过滤 → C++ 检索 → 本地模型 → 保存问答/引用

PostgreSQL
  ├─ projects / documents / document_pages / document_chunks
  └─ qa_sessions / qa_messages / qa_retrieval_records / qa_citations
```

`qa_citations` 保存资料名称、页码和原文摘录快照。删除一份资料后，历史问答仍能显示当时的引用内容；删除整个项目时，数据库外键级联清理项目内全部数据。

## 接口

| 方法 | 地址 | 作用 |
| --- | --- | --- |
| POST | `/api/v1/projects` | 创建学习项目 |
| POST | `/api/v1/documents` | 上传文字型 PDF，表单字段为 `projectId`、`documentType`、`file` |
| GET | `/api/v1/documents?projectId=1` | 获取当前项目资料状态 |
| DELETE | `/api/v1/documents/{id}?projectId=1` | 删除资料、索引和本机文件 |
| POST | `/api/v1/qa` | 提问，JSON 包含 `projectId`、`question` 和可选 `sessionId` |

问答成功响应中的 `citations` 包含 `documentName`、`pageNumber`、`excerpt` 和检索分数。`status` 是 `ANSWERED` 或 `INSUFFICIENT_EVIDENCE`。

## 本地运行与验证

1. 配置 PostgreSQL 连接：`STUDYPILOT_DB_URL`、`STUDYPILOT_DB_USERNAME`、`STUDYPILOT_DB_PASSWORD`。
2. 按 [数据库实现说明](../../backend/docs/数据库实现说明.md) 初始化 Schema。
3. 启动 C++ 服务与本地模型服务；健康接口 `/api/v1/health/dependencies` 应显示模型就绪。
4. 在 `backend` 运行 `./mvnw.cmd test`，在 `frontend` 运行 `pnpm run check`。
5. 分别启动 Spring Boot 与 Vite，浏览器打开 `/projects`，创建项目、上传 PDF，再进入问答页验证引用。

需要一次不依赖外部数据库的完整产品验证时，在 C++ 服务和模型已启动的情况下运行：

```powershell
./mvnw.cmd -Dstudypilot.e2e=true -Dtest=GroundedQaEndToEndTest test
```

测试自行创建并关闭临时 PostgreSQL，按真实 HTTP 路径完成项目创建、PDF 导入、检索问答和资料/索引清理。

当前只支持文字型 PDF，不包含 OCR。模型服务或检索服务不可用时，统一返回可识别的外部服务错误，资料状态不会伪装为已就绪。

没有配置数据库时，后端仍可启动，用于检查 `/api/v1/health` 和 `/api/v1/health/dependencies`；此模式不会装配项目、资料和问答接口。这样可以先确认 Java、C++ 服务和本地模型是否正常，再填写数据库环境变量进入完整产品模式。
