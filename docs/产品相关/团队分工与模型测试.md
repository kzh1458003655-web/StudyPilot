# 团队分工与模型测试

本文按当前可运行版本划分三名成员的工作。分工以用户可见的业务模块为主，每名成员都需要完成本模块的前端、Java 后端、PostgreSQL 数据访问、AI 或算法逻辑以及测试，不再按“一个人只做前端、一个人只做后端”的方式拆分。

## 1. 分工总览

| 成员 | 负责模块 | 独立测试模型 | 主要展示内容 |
| --- | --- | --- | --- |
| 成员 A | 课程资料与知识问答 | Qwen3.5-4B Q4_K_M | PDF 上传与管理、RAG 问答、引用页码、问答历史 |
| 成员 B | 智能组卷、在线作答与测评 | Qwen3-4B Q4_K_M | 按要求出题、历史练习、重复作答、客观题与简答题评分 |
| 成员 C | 历年试卷考频分析 | Phi-4-mini-instruct Q4_K_M | 试卷识别、题目切分、知识点归一、考频统计 |

模型测试是共同的选型实验。每名成员负责一款模型的数据采集和复核，最终运行时仍由全组使用同一默认模型。当前启动脚本加载 Qwen3.5-4B Q4_K_M。

## 2. 成员 A：课程资料与知识问答

成员 A 负责课程资料进入系统后，到用户得到回答的完整链路：

- 完成课程创建、切换、归档与恢复相关交互；
- 在问答页右侧实现文字型 PDF 的上传、状态展示和删除；
- 使用 PDFBox 提取分页文字并完成文本分块；
- 调用 C++ 服务建立和删除项目内检索索引；
- 根据当前课程资料执行检索增强问答；
- 由服务端根据检索快照生成资料名、页码和原文引用；
- 没有资料或没有命中资料时，调用本地模型按通用知识回答，但不生成虚假引用；
- 保存并恢复当前课程的问答历史；
- 验证课程隔离、文件限制、引用准确性和异常处理。

该成员重点说明 PDF 处理、RAG 数据流、检索白名单、会话持久化以及 `documents`、`document_pages`、`document_chunks`、`qa_sessions`、`qa_messages`、`qa_citations` 等数据表。

## 3. 成员 B：智能组卷、在线作答与测评

在线作答和测评没有独立的一级入口，用户从智能组卷页面进入，因此这两部分归入同一个模块：

- 实现智能组卷页面和自然语言出题要求；
- 允许用户不上传指定参考试卷直接生成练习；
- 有课程资料时将其作为补充依据，没有资料时按课程名称和用户要求出题；
- 调用本地模型生成单项选择题和简答题；
- 校验题数、题型、选项、答案、评分点和 JSON 结构；
- 保存和显示历史练习，支持删除和重新作答；
- 生成任务在模块切换后继续运行，返回页面后恢复结果；
- 每次作答创建新的 `attempt`，避免覆盖以前的成绩；
- 选择题由程序确定性判分，简答题由模型按照评分点辅助评分；
- 展示总分、逐题得分和反馈，并处理模型评分解析失败；
- 验证生成超时、结构错误、重复作答和跨课程访问。

该成员重点说明结构化模型输出、生成结果校验、作答状态机以及 `mock_exams`、`mock_exam_items`、`exam_attempts`、`attempt_answers`、`grading_details` 等数据表。

## 4. 成员 C：历年试卷考频分析

成员 C 负责独立的考频分析页面及其数据处理流程：

- 从当前课程资料中自动筛选历年试卷，无需用户填写资料编号；
- 显示试卷名称、页数、处理状态和分析入口；
- 从文字型 PDF 中读取历年试卷内容；
- 根据题号标记切分试题，并保留来源页码；
- 使用确定性词典提取并归一知识点；
- 一道题可以关联多个知识点，同一题对同一知识点只计一次；
- 按当前课程统计各知识点对应的题目数量并排序展示；
- 对无法匹配知识点的题目计入“待人工补充”，不伪造分析结果；
- 重新分析同一份试卷时替换旧结果，避免重复累计；
- 验证不同题号格式、跨页题目、重复题号、课程隔离和统计准确性。

该成员重点说明题目切分规则、知识点归一方法、统计口径以及 `source_questions`、`question_knowledge_points` 等数据表。当前版本只处理具有文字层并带明显题号的 PDF，不包含 OCR、图片题理解和模型语义归一。

## 5. 共同工作

三人共同维护前后端接口约定、课程数据边界、C++ 检索与推理服务、启动脚本和系统联调。最终演示按照下面的顺序完成：

```text
创建课程并上传资料
→ 课程问答与引用展示
→ 上传历年试卷并查看考频
→ 按要求生成练习
→ 在线作答并查看测评结果
→ 再次作答或删除历史练习
```

## 6. 模型测试方法

三款模型均使用 Q4_K_M GGUF，在 RTX 4060 Laptop 8 GB、llama.cpp、4096 上下文、单并发条件下依次测试。测试集包括：

- 60 道计算机专业选择题；
- 6 道资料依据题；
- 6 组结构化出题任务；
- 8 道答题评分任务；
- 3 次固定长度性能请求。

综合分权重为：选择题正确率 45%、资料依据能力 15%、出题结构 15%、评分准确性 15%、性能 8%、请求成功率 2%。

## 7. 已有测试结果

| 指标 | Qwen3.5-4B | Qwen3-4B | Phi-4-mini-instruct |
| --- | ---: | ---: | ---: |
| 选择题正确率 | 93.33% | 90.00% | 36.67% |
| 选择题格式正确率 | 100.00% | 100.00% | 100.00% |
| 资料依据题正确率 | 83.33% | 83.33% | 16.67% |
| 出题结构得分 | 22.22% | 22.22% | 8.33% |
| 评分平均绝对误差 | 0.375 | 0.625 | 2.125 |
| 评分任务得分 | 92.50 | 87.50 | 57.50 |
| 平均首 Token 时间 | 0.194 秒 | 0.067 秒 | 0.048 秒 |
| 平均生成速度 | 49.759 token/s | 58.592 token/s | 61.499 token/s |
| 峰值 GPU 显存 | 5194 MiB | 5223 MiB | 5144 MiB |
| 请求成功率 | 97.56% | 100.00% | 95.12% |
| 模型文件大小 | 2.553 GiB | 2.326 GiB | 2.321 GiB |
| 综合得分 | 78.62 | 78.37 | 38.78 |

Qwen3.5-4B 的综合分最高，Qwen3-4B 的延迟、速度和结构输出更稳定，两者差距较小。Phi-4-mini-instruct 速度最快，但中文专业任务表现不足。仓库当前继续使用 Qwen3.5-4B 作为默认模型；后续如果更看重结构化出题稳定性，可以再次复核 Qwen3-4B。

原始数据位于 `tests/model-benchmark/benchmark-summary.csv`，测试脚本、汇总程序和截图保存在 `tests/model-benchmark/`。
