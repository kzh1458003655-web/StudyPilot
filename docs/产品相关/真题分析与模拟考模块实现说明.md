# 真题分析与模拟考模块实现说明

## 已实现能力

模块以项目为边界，分为两条独立流程：

1. 用户上传 `PAST_EXAM` 类型的文字型 PDF 后，输入资料编号即可触发真题分析。后端按编号划分文本题目，对进程、线程、死锁、内存、事务、SQL 等术语归一，并按“题目—知识点”关系统计频次。无法归一的题目会计入待人工补充，不会伪造统计结果。
2. 用户点击生成模拟卷后，后端只从当前项目状态为 `READY` 的教材、讲义和知识点资料中检索证据，调用本地模型生成 JSON。程序要求固定产出 2 道单选题和 2 道简答题；题型、选项、答案、分值、知识点、重复题干和资料来源均校验通过后，才保存为试卷。

生成的题目是新题，不读取或改写历年真题题干。真题仅用于考频分析；知识资料用于提供出题依据。

## 数据和项目隔离

`source_questions`、`question_knowledge_points` 保存真题分析结果；`mock_exams`、`mock_exam_items` 保存生成后的固定试卷；`question_validation_records` 保存结构化输出已通过校验的证据。所有查询均带 `projectId`，读取试卷时也再次校验试卷归属，避免跨项目访问。

选项使用 PostgreSQL `JSONB` 保存。`PostgreSqlSchemaIntegrationTest` 在真实 Embedded PostgreSQL 中验证了试卷、题目、JSONB 选项、校验记录以及跨项目读取拒绝。

## 页面和接口

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| POST | `/api/v1/exams/past-papers/{documentId}/analysis?projectId=...` | 分析一份已就绪的历年真题 |
| GET | `/api/v1/exams/knowledge-points?projectId=...` | 读取当前项目知识点考频 |
| POST | `/api/v1/exams/generate?projectId=...` | 生成并保存固定四题模拟卷 |
| GET | `/api/v1/exams/{examId}?projectId=...` | 读取本项目生成的模拟卷 |

前端地址是 `/projects/:projectId/exams`。资料上传成功后会显示资料编号，便于将 `PAST_EXAM` 资料送入分析。

## 验证方式

```powershell
# 后端算法、控制器、结构化校验与真实 PostgreSQL
cd backend
./mvnw.cmd -Dtest=PostgreSqlSchemaIntegrationTest,ExamControllerTest,PastPaperAnalysisServiceTest,MockExamGenerationServiceTest,GeneratedExamValidatorTest test

# 受控外部 Gateway 的完整 HTTP 工作流（临时 PostgreSQL）
./mvnw.cmd -Dstudypilot.e2e=true -Dtest=MockExamWorkflowEndToEndTest test

# 前端静态检查、单测与生产构建
cd ../frontend
pnpm run check
```

`MockExamWorkflowEndToEndTest` 使用真实 Spring MVC、PDF 解析、项目/资料/试卷 REST 接口和临时 PostgreSQL。为保证 JSON 格式的测试可重复，检索、索引与模型网关使用受控实现；真实 C++ 索引和本地模型的连通性由资料问答的 `GroundedQaEndToEndTest` 单独验证。

应用资料默认保存在 `D:\大四课程设计\StudyPilot-runtime\uploads`；可用 `STUDYPILOT_STORAGE_ROOT` 改到组员电脑上的其他位置。测试证据和导出物默认放在 `D:\大四课程设计\StudyPilot-output`。
