# 考频分析、智能组卷与测评实现说明

## 1. 页面划分

当前版本将相关能力拆成两条用户流程：

- **考频分析**是独立一级页面，负责历年试卷识别、题目切分、知识点归一和统计；
- **智能组卷**负责生成和管理练习，在线作答与测评从具体练习进入。

团队分工中，考频分析归成员 C；智能组卷、在线作答和测评归成员 B。代码层面两者仍共享 `exam` 包中的试卷数据结构和接口。

## 2. 考频分析

用户在知识问答页右侧上传 PDF。系统将识别为 `PAST_EXAM` 的资料显示在考频分析页面，用户点击“开始分析”即可处理，不需要手工填写资料编号。

后端当前采用确定性分析流程：

1. 读取当前课程、当前试卷已经提取的分页文字；
2. 识别 `Problem N`、`Question N`、`第 N 题`、`(N)`、`N.` 等题号标记；
3. 切分题目并记录起始页码；
4. 用内置词典匹配算法、数学、操作系统和数据库知识点；
5. 将近义表达归一为稳定名称；
6. 在同一事务中替换该试卷以前的分析结果；
7. 按当前课程统计每个知识点关联的题目数量。

没有匹配到知识点的题目计入“待人工补充”。该数字表示题目已经切分，但当前词典无法给出可信知识点，并不表示系统丢失了题目。

当前考频是“知识点被多少道题考查”的统计，不是关键词在文本中出现多少次。一道题可以关联多个知识点，但同一道题不会重复计算同一个知识点。

## 3. 智能组卷

用户可以输入题量、难度、题型或知识范围，也可以留空直接生成默认练习。生成过程不要求指定一份参考试卷：

- 有已就绪的课程知识资料时，系统检索相关片段作为补充依据；
- 没有课程资料时，模型根据课程名称和用户要求直接出题；
- 当前版本固定生成 2 道单项选择题和 2 道简答题；
- 后端校验题型、题数、选项、答案、解析、知识点、分值和 JSON 结构；
- 校验通过后才写入 PostgreSQL。

生成任务由前端全局状态保存。用户切换到问答或考频页面时请求继续执行，返回智能组卷页面后刷新历史记录。模型调用超时按本地推理所需时间单独放宽。

页面显示本课程已经生成的练习，支持重新作答和删除。删除练习会由数据库外键一并清理相关作答记录。

## 4. 在线作答与测评

用户从历史练习或生成结果进入 `/projects/:projectId/exams/:examId/take`。页面加载练习后直接创建新的作答记录，无需再点击“开始作答”。

- 单项选择题使用标准答案确定性判分；
- 简答题将用户答案、标准答案和评分要求交给本地模型；
- 模型必须返回包含 `score` 和 `feedback` 的严格 JSON；
- 后端验证分数范围并保存逐题反馈；
- 页面显示总分和每道题的评分结果；
- 已提交的练习再次打开时创建新的 `attempt`，可以重复练习。

## 5. 数据表

| 数据表 | 用途 |
| --- | --- |
| `source_questions` | 保存从历年试卷切分出的题目、来源页码和文本快照 |
| `question_knowledge_points` | 保存题目与归一知识点的关联 |
| `mock_exams` | 保存生成的练习卷 |
| `mock_exam_items` | 保存练习题、选项、答案、解析和知识点 |
| `question_validation_records` | 保存生成题目的校验记录 |
| `exam_attempts` | 保存每一次独立作答 |
| `attempt_answers` | 保存用户答案、得分和反馈 |
| `grading_details` | 保存评分依据和模型运行关联 |
| `wrong_questions`、`mastery_records`、`recommendation_records` | 保存错题、掌握度和建议数据，当前尚无完整独立页面 |

## 6. 接口

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| `POST` | `/api/v1/exams/past-papers/{documentId}/analysis?projectId=...` | 分析一份历年试卷 |
| `GET` | `/api/v1/exams/knowledge-points?projectId=...` | 查询当前课程考频 |
| `POST` | `/api/v1/exams/generate?projectId=...` | 生成练习 |
| `GET` | `/api/v1/exams?projectId=...` | 查询历史练习 |
| `GET` | `/api/v1/exams/{examId}?projectId=...` | 读取练习 |
| `DELETE` | `/api/v1/exams/{examId}?projectId=...` | 删除练习 |
| `POST` | `/api/v1/assessments/attempts` | 创建新作答 |
| `POST` | `/api/v1/assessments/attempts/{attemptId}/submit?projectId=...` | 提交答案并评分 |

## 7. 验证重点

考频分析重点验证题目切分数量、页码、同义知识点归一、重复分析替换和课程隔离。智能组卷重点验证无资料生成、结构化输出、超时处理、历史记录和删除。测评重点验证选项布局、答案提交、简答题 JSON 解析和重复作答。

后端可运行 `PastPaperAnalysisServiceTest`、`MockExamGenerationServiceTest`、`GeneratedExamValidatorTest`、`AssessmentServiceTest` 和相关集成测试；前端通过 `pnpm run check` 验证类型、单元测试和生产构建。
