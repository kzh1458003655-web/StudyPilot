# 项目最终需求结论

> 实施状态（2026-09-09）：三个产品模块与系统级验证已完成，当前进行最终交付一致性审计。本文保留需求与扩展方向；已实现页面、接口和功能边界以 [产品架构与当前实现](产品架构.md) 为准。具体任务状态见 [任务清单](../harness/feature_list.json)。

## 一 项目名称

推荐题目：

**基于本地大语言模型与RAG的多场景智能备考系统**

项目不再局限于单门课程的资料检索和复习规划，而是面向课程考试、考研、笔试和面试等以文本资料为主的备考场景。

## 二 项目目标

系统允许用户上传教材、讲义、知识点、历年真题和参考答案等文字型PDF资料，在本地构建个人备考知识库。

系统以 RAG、真题数据分析、结构化题目生成和模型辅助评分为主要技术路线，实现以下完整闭环：

**资料导入与理解 → 知识问答 → 考频分析 → 智能组卷 → 在线作答 → 自动测评与逐题反馈**

系统重点体现人工智能应用、检索与推荐算法、数据库设计、前后端开发、本地模型部署和软件工程实践，不以Agent作为必须实现的核心目标。

## 三 核心模块

当前产品以用户可见的三个入口组织功能，在线作答和测评从智能组卷进入。

### 1 课程资料与知识问答

用户在知识问答页面右侧上传、查看和删除文字型 PDF。系统使用 PDFBox 提取分页文字并分块，再由 C++ 服务建立项目内检索索引。

提问时优先检索当前课程资料。命中资料后，模型根据原文片段回答，页面显示由服务端生成的资料名称、页码和摘录；没有资料或没有命中相关内容时，模型使用通用知识回答，但不生成虚假引用。问答历史保存在 PostgreSQL 中，刷新或切换模块后可以恢复。

主要功能包括：

- 课程创建、切换、归档和恢复；
- 文字型 PDF 上传、状态展示和删除；
- 分页提取、文本分块和 C++ 检索索引；
- 基于当前课程资料的 RAG 问答；
- 无资料时的通用知识回答；
- 真实资料名称、页码和原文引用；
- 问答会话和历史消息保存；
- 不同课程之间的数据隔离。

### 2 智能组卷、在线作答与测评

用户可以输入题型、难度或知识范围，也可以不填写要求直接生成默认练习。系统有课程资料时将检索结果作为补充依据，没有资料时根据课程名称和用户要求直接出题。当前版本固定生成 2 道单项选择题和 2 道简答题。

模型输出必须经过 JSON 解析以及题数、题型、选项、答案、解析、知识点和分值校验。生成任务在用户切换模块后继续执行。已生成练习保存在历史列表中，可以删除或再次作答。

用户打开练习后直接开始填写答案。每次打开都会建立新的作答记录，已提交的练习仍可重复完成。选择题由程序确定性判分，简答题由模型根据参考答案和评分要求返回分数与反馈。

主要功能包括：

- 自然语言出题要求和无资料直接生成；
- 单项选择题与简答题结构化生成；
- 模型输出校验和错误处理；
- 后台生成状态和历史练习；
- 删除练习与重复作答；
- 选择题规则判分；
- 简答题模型辅助评分；
- 总分和逐题反馈展示。

### 3 历年试卷考频分析

考频分析使用独立页面。系统自动列出当前课程中已经识别的历年试卷，用户点击试卷即可分析，不需要填写资料编号。

当前版本从 PDF 文字中识别题号并切分试题，保留来源页码，然后使用确定性词典提取和归一知识点。统计口径是每个知识点被多少道题考查，不是关键词在试卷中出现多少次。一道题可以对应多个知识点，同一道题对同一知识点最多计算一次。

没有匹配到知识点的题目计入“待人工补充”，不生成虚假结果。重新分析同一试卷时会替换以前的分析记录，避免重复累计。

主要功能包括：

- 自动筛选当前课程的历年试卷；
- 中文、英文常见题号识别；
- 题目切分和来源页码保存；
- 知识点匹配与名称归一；
- 按题目维度统计知识点频次；
- 无法归一题目的待补充计数；
- 重复分析替换和课程隔离。
## 四 真题分析范围与生成题型范围

### 4.1 真题输入与知识点分析范围

系统只处理能够直接提取文字的PDF，不增加OCR、图像识别或多模态理解能力。真题中的原始题型不受白名单限制：只要一道题能够通过提取出的文字完整表达，系统就应在临时处理过程中划分该题并提取知识点。

因此，多项选择题、填空题、判断题、简答题、证明题、编程题、SQL实操题和其他文本型题目都可以参与知识点分析。系统关注的是每道题考查了哪些知识点，而不是将原题转换成可直接作答的题库记录。

对于扫描件以及依赖图片、图表、作图、音视频、复杂公式排版或外部操作才能理解的题目，如果提取出的文字不足以完整表达题意，则标记为“未分析”或“待人工确认”，不纳入知识点频次统计。系统不通过新增OCR或视觉模型解决此类内容。

### 4.2 模拟题生成与测评范围

题型白名单只应用于系统最终生成、在线作答和自动测评的模拟题。系统仅支持：

1. **单项选择题**
2. **简答题**

单项选择题必须具有明确题干、候选选项和唯一正确答案。简答题采用纯文本作答，并具有参考答案或明确评分要点。

模型生成的新题必须经过白名单和完整性检查。生成结果无法确定为上述两种题型，或者题干、选项、答案、评分要点、资料依据不完整时，不得保存为正式模拟题，也不得进入在线测评流程。

上述限制只约束系统生成和测评的题型，不影响系统从其他文本型真题中提取知识点。

## 五 复习规划功能的处理

复习规划不再作为当前版本的独立模块，也没有一级页面。数据库保留了掌握度、错题、建议和学习任务的数据结构，测评流程会写入其中一部分记录，但当前交付页面只展示本次总分和逐题反馈。

基于历史成绩生成薄弱点报告、巩固题或短期计划属于后续扩展，不能在答辩中作为已经完成的页面功能展示。

## 六 Agent的定位

Agent不是项目的核心目标，也不是三个模块的强制实现方式。

资料问答使用固定 RAG 流程；考频分析使用题目切分、词典归一和统计流程；智能组卷使用结构化生成与规则校验；测评使用规则判分和模型辅助评分。

只有当模型需要根据中间结果自主选择工具、决定下一步操作，并在校验失败后自行调整和继续执行时，才将该功能称为Agent。

如果所有步骤由程序按照预定顺序调用，则应称为智能工作流，不应为了突出技术性而强行包装成Agent。

当前版本没有让模型自主选择工具或改变执行路线，因此应称为本地 AI 智能工作流，而不是完整 Agent 系统。

## 七 系统整体架构

系统继续采用现有的分层架构：

- Vue负责页面展示和用户交互；
- Spring Boot负责业务接口、输入校验、数据库事务和流程控制；
- PostgreSQL 保存资料、题目、试卷、作答、引用、错题、掌握度和推荐记录；部署时可选择 Supabase 提供的 PostgreSQL 服务；
- C++服务负责文本检索、本地模型请求代理和推理任务管理；
- llama.cpp负责运行本地大语言模型。

三个业务模块共享资料库、检索索引、本地模型服务、用户作答数据和统一的运行记录，不建设三套相互独立的系统。

当前主要页面包括：

- 课程首页与新建课程；
- 知识问答与资料管理；
- 智能组卷与历史练习；
- 历年试卷考频分析；
- 在线作答与测评。

## 八 模块化分工原则

项目按照当前三个用户功能模块分工。每名成员负责一条能够独立演示的完整业务链路，并完成该模块的前端页面、Java 接口、PostgreSQL 数据访问、AI 或算法逻辑和测试。

| 成员 | 负责模块 | 独立测试模型 | 主要成果 |
| --- | --- | --- | --- |
| 成员 A | 课程资料与知识问答 | Qwen3.5-4B Q4_K_M | PDF 处理、RAG 检索、引用展示和问答历史 |
| 成员 B | 智能组卷、在线作答与测评 | Qwen3-4B Q4_K_M | 结构化出题、练习管理、重复作答和自动评分 |
| 成员 C | 历年试卷考频分析 | Phi-4-mini-instruct Q4_K_M | 试题切分、知识点归一和考频统计 |

成员 A 重点负责资料从上传、解析、索引到问答和引用展示的完整链路。成员 B 负责从生成练习、保存历史、在线作答到评分反馈的完整链路。成员 C 负责从识别历年试卷、切分题目、归一知识点到展示考频的完整链路。

三人共同维护前后端接口约定、课程数据边界、C++ 服务、启动脚本和最终联调。每人独立测试一款本地模型并复核数据，最终系统仍统一使用一款默认模型。详细分工和测试结果见 [团队分工与模型测试](团队分工与模型测试.md)。

## 九 最终演示流程

系统最终应能够完成以下连续演示：

1. 创建两门课程，演示课程切换以及资料和历史记录隔离；
2. 在知识问答页上传教材或讲义，提问并查看资料名称、页码和原文；
3. 在没有资料命中的情况下提问，展示本地模型的通用知识回答；
4. 上传历年试卷，在考频分析页直接选择试卷开始分析；
5. 展示识别题数、已归一题数、待人工补充题数和知识点频次；
6. 进入智能组卷，输入要求或直接生成默认练习；
7. 在线完成选择题和简答题，提交后查看总分和逐题反馈；
8. 返回历史练习，演示重新作答和删除；
9. 归档并恢复课程，确认课程数据仍然存在。

项目最终形成一套能够在本机离线运行的智能备考系统，实际闭环覆盖课程资料管理、知识问答、考频分析、智能组卷和在线测评。
