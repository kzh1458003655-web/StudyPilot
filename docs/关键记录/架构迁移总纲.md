## 当前原型

当前仓库中的可运行实现仍属于课程版原型：

- 后端是 Java 21、Spring Boot 3.5 和本地 MySQL，源码集中在 `cn.studypilot` 根包；
- 前端使用单页 HTML、全局 Vue 构建、`app.js` 和 `style.css`；
- C++ 服务承担页级检索、模型代理、请求队列、取消和运行指标；
- 数据以课程作为隔离边界；
- 已实现 PDF、带引用问答和复习计划等行为；
- 尚未形成目标文档要求的项目化、模块化和三大产品模块闭环。

上述描述只用于确定迁移起点，不代表目标架构。

## 目标架构

- 产品以备考项目作为最高业务边界；
- 后端采用单个 Spring Boot 模块化单体；
- 后端按 `common`、`document`、`model`、`retrieval`、`qa`、`exam`、`assessment` 组织；
- 前端采用 Vue 3、TypeScript、Vite，并按 `app`、`modules`、`shared`、`types` 分层；
- 后端通过 `RetrievalGateway` 和 `ModelGateway` 调用独立 C++ 与本地模型服务；
- 数据库目标为 Supabase 托管 PostgreSQL，业务数据位于 `studypilot` Schema；
- 产品功能在架构基础链路通过验证后按三个业务模块实现。

任务状态和验收条件见 [feature_list.json](../harness/feature_list.json)。

## 阶段门禁

- `ARCH-001` 未验证前，不删除、搬迁或批量改写旧业务代码。
- 架构任务未全部验证前，产品任务保持 `blocked`。
- 数据库表和 Repository 不得在正式记录缺失时自由扩展。
- 公共接口变更必须先更新契约和消费者影响说明。
- 每个阶段以可复现验证和文档一致性为完成依据，不以文件数量或主观判断代替。

## 旧实现与目标架构的处理

后端架构文档要求目标骨架不直接迁移旧 Java 类、配置和 SQL；同时项目允许复用已验证行为，避免完全从零重写。统一处理方式是：

1. 旧实现保存在独立归档分支和仓库外 worktree。
2. 先通过测试或输入输出记录建立行为基线。
3. 在目标模块中重新实现或提取可复用的纯逻辑。
4. 不复制旧包结构、数据库耦合和本机路径。
5. 在 [重构复用清单](重构复用清单.md) 中记录来源、目标、改造和证据。
