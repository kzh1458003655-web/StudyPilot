# 接口与数据契约索引

本文件是跨层接口的索引，不复制每个模块的完整 DTO。具体契约在相应架构或模块文档中定义，并由实现和契约测试验证。

## 当前状态

当前运行分支的后端已完成 `ARCH-002` 骨架；课程版接口只保留在归档分支中作为行为参考，尚未迁入目标产品接口、SSE、数据库字段或 C++ 协议。

## 目标后端接口

目标约定来自 [后端框架设计](../../backend/docs/后端框架设计.md)：

```text
/api/v1/health
/api/v1/documents
/api/v1/qa
/api/v1/exams
/api/v1/assessments
```

- 普通响应使用统一数据和请求 ID 结构；
- SSE 流式响应不套普通响应包装；
- 请求和响应 DTO 使用 Java `record`；
- Controller 不返回数据库模型；
- 时间使用 ISO 8601；
- AI 输出除反序列化外还必须通过业务规则校验；
- 错误响应包含稳定错误码、用户可读信息、请求 ID 和时间。

## Gateway 边界

### ModelGateway

负责模型请求、普通或流式响应、超时和外部错误转换。它不检索资料、不组装业务工作流、不保存业务实体，也不开启数据库事务。

### RetrievalGateway

负责向独立检索服务发送索引和检索请求。业务模块不能依赖 C++ 内部索引结构、端口管理或进程生命周期。

协议端点、错误映射、队列和取消边界见 [AI 服务协议（ARCH-004）](AI服务协议-ARCH-004.md)。

### ModelRunService

由业务工作流调用，保存模型名称、任务类型、参数摘要、耗时、结束原因和成功状态，不保存完整提示词、资料全文或密钥。

## 前端契约边界

目标约定来自 [前端框架设计](../../frontend/前端框架设计.md)：

- 具体请求只出现在模块 API；
- 组件、页面和 Store 不拼接接口路径；
- 外部响应先通过运行时 Schema，再由 mapper 转为内部模型；
- 外部 DTO 不直接进入组件和 Store；
- 普通 HTTP 请求使用统一 Axios 实例；
- 协议适配器只处理传输，不包含业务规则；
- 跨模块只能使用对方 `index.ts` 暴露的公共能力。
