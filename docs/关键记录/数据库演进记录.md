# 数据库演进记录

本文档记录数据库从当前原型到目标架构的演进事实、决策和验证。完整目标约束以 [后端框架设计](../../backend/docs/后端框架设计.md) 为准；表字段和测试原理见 [数据库实现说明](../../backend/docs/数据库实现说明.md)。

## 当前状态

- 当前运行原型使用本地 MySQL 8.4；
- 当前后端通过 Spring JDBC 访问数据库；
- 当前数据模型以课程、文档、会话、消息和计划为主；
- 当前目标工程不迁移 MySQL 数据，也不连接 Supabase 生产库。

## 目标基线

- 数据库为 Supabase 托管 PostgreSQL；
- Spring Boot 只通过 PostgreSQL JDBC 连接；
- 不使用前端直连 Data API、Supabase Auth 或 Supabase Storage；
- 业务表统一位于 `studypilot` Schema；
- 项目为最高业务和数据隔离边界；
- 主键、时间、JSONB、外键删除策略和索引遵循后端架构文档；
- 仓库不保存真实连接地址、项目标识、用户名、密码或 Service Role Key。

目标 SQL 顺序：

```text
00-schema.sql
10-common.sql
20-document.sql
30-qa.sql
40-exam.sql
50-assessment.sql
90-indexes.sql
```

该顺序已由 `DB-001` 实现并由隔离 PostgreSQL 实例验证。

## 表归属边界

| 范围 | 目标数据 |
| --- | --- |
| common | 模型运行和公共审计元数据 |
| document | 项目资料、页面、文本块和索引状态 |
| qa | 会话、消息、检索记录和引用快照 |
| exam | 真题知识点记录、组卷蓝图、模拟试卷和题目 |
| assessment | 作答、答案、评分、错题、掌握度和推荐 |

`DB-001` 已建立当前产品边界所需的最小字段、外键、检查约束和索引。后续产品任务只能通过显式迁移扩展，而不能静默改变已执行的建表脚本。

## 验证原则

- Schema 在隔离 PostgreSQL 环境中重复执行和验证；
- 正式数据存在后，结构变化使用明确的迁移脚本，不覆盖旧 SQL 假设自动升级；
- 外键删除策略必须符合项目硬删除、资料历史快照和试卷冻结规则；
- 只做静态检查不能宣称完成真实数据库验证；
- 外部数据库不可用时记录阻塞，不使用生产凭据替代测试环境；
- 验证证据同步写入任务 `evidence` 和 Harness 验证记录。

## 演进记录

### 2026-09-08 · DB-001 · 初始 PostgreSQL Schema 与 JDBC 边界

- **变更原因**：课程版 MySQL 表结构不能表达项目隔离、资料分块引用、真题分析和独立作答诊断，也不符合目标 PostgreSQL 架构。
- **受影响表和字段**：在 `studypilot` Schema 建立 24 张表，覆盖项目与模型运行、资料与索引、问答引用、真题与组卷、作答和推荐。时间统一使用 `TIMESTAMPTZ`，模型参数、组卷规格、选项和评分依据使用 `JSONB`。
- **DDL 与访问方式**：新增七份顺序 SQL、可选 PostgreSQL JDBC 配置、`NamedParameterJdbcTemplate` 和 `ProjectRepository` 示例。只在显式提供三个 `STUDYPILOT_DB_*` 变量时创建连接池。
- **数据兼容方式**：这是绿地目标架构，未迁移旧 MySQL 数据；旧课程版保留在归档分支与仓库外 worktree 供参考。
- **回退和备份方式**：未部署到共享库时直接丢弃隔离测试实例。将来首次部署前导出目标 Schema；正式结构变更新增独立 `ALTER TABLE` 脚本，按记录中的逆向 DDL 回退。
- **索引与性能影响**：为项目、外键、会话、题目、作答、掌握度和待办状态建立索引；避免在引用快照全文上建索引，以免扩大写入开销。
- **验证环境和命令**：Windows x86_64、测试范围 Embedded PostgreSQL 14.22；执行 `backend\\mvnw.cmd -Dtest=PostgreSqlSchemaIntegrationTest test`。
- **验证结果**：通过。测试连续执行两遍完整 DDL，确认 24 张表、JSONB 列、资料分块写入和项目级级联删除均由真实 PostgreSQL 解释。

## 2026-09-08 · PROD-002 · 真题分析与模拟卷持久化

- **变更原因**：需要将文本真题的知识点分析与可复现的模拟卷生成接入目标 PostgreSQL 架构。
- **受影响表和字段**：使用既有 `source_questions`、`question_knowledge_points`、`mock_exams`、`mock_exam_items` 和 `question_validation_records`；未改动已提交 DDL。
- **访问方式**：新增 JDBC Repository 将选项写入 JSONB，并以 `project_id` 约束读取；结构化生成在保存前完成校验。
- **兼容与回退**：当前为未部署的绿地功能；回退时移除应用代码，不需要转换现有数据。正式共享库部署后如需改变表结构，必须增加单独迁移脚本。
- **验证**：`PostgreSqlSchemaIntegrationTest` 与 `MockExamWorkflowEndToEndTest` 均通过。
