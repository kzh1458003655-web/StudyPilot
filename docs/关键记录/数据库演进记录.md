# 数据库演进记录

本文档记录数据库从当前原型到目标架构的演进事实、决策和验证。完整目标约束以 [后端框架设计](../../backend/后端框架设计.md) 为准。

## 当前状态

- 当前运行原型使用本地 MySQL 8.4；
- 当前后端通过 Spring JDBC 访问数据库；
- 当前数据模型以课程、文档、会话、消息和计划为主；
- 当前 Harness 任务不修改 SQL、不迁移数据、不连接 Supabase。

## 目标基线

- 数据库为 Supabase 托管 PostgreSQL；
- Spring Boot 只通过 PostgreSQL JDBC 连接；
- 不使用前端直连 Data API、Supabase Auth 或 Supabase Storage；
- 业务表统一位于 `studypilot` Schema；
- 项目为最高业务和数据隔离边界；
- 主键、时间、JSONB、外键删除策略和索引遵循后端架构文档；
- 仓库不保存真实连接地址、项目标识、用户名、密码或 Service Role Key。

目标 SQL 顺序：

```text
00-schema.sql
10-common.sql
20-document.sql
30-qa.sql
40-exam.sql
50-assessment.sql
90-indexes.sql
```

当前仅记录目标顺序；实际 SQL 文件和 Repository 骨架由 `DB-001` 完成。

## 表归属边界

| 范围 | 目标数据 |
| --- | --- |
| common | 模型运行和公共审计元数据 |
| document | 项目资料、页面、文本块和索引状态 |
| qa | 会话、消息、检索记录和引用快照 |
| exam | 真题知识点记录、组卷蓝图、模拟试卷和题目 |
| assessment | 作答、答案、评分、错题、掌握度和推荐 |

完整字段不能在 Harness 阶段提前锁死，由对应任务根据产品边界和查询需求确定。

## 验证原则

- Schema 在隔离 PostgreSQL 环境中重复执行和验证；
- 正式数据存在后，结构变化使用明确的迁移脚本，不覆盖旧 SQL 假设自动升级；
- 外键删除策略必须符合项目硬删除、资料历史快照和试卷冻结规则；
- 只做静态检查不能宣称完成真实数据库验证；
- 外部数据库不可用时记录阻塞，不使用生产凭据替代测试环境；
- 验证证据同步写入任务 `evidence` 和 Harness 验证记录。
