# ADR-002：架构重构先于产品实现

- 状态：已接受
- 日期：2026-09-08

## 背景

当前课程版原型与已经确认的项目化、模块化目标架构差异较大。继续直接添加产品功能会扩大旧结构的耦合，并提高后续迁移成本。

## 决定

- Harness 建设完成后，先执行 `ARCH-001` 至 `INT-001`。
- `INT-001` 验证通过前，所有 `PROD-*` 任务保持 `blocked`。
- 当前 `HARNESS-001` 只建设工作环境，不执行架构重构。
- 架构阶段必须建立可编译骨架、公共契约、数据库边界和基础链路证据。

## 备选方案

- 边开发产品边重构：容易把临时兼容写成长期架构。
- 先完成某个产品模块再重构：会让该模块成为迁移特例。

## 影响

- 短期看不到新增产品功能。
- 后续三个产品模块拥有稳定的目录、接口和数据边界。
- 任务依赖由 `feature_list.json` 强制表达。

## 验证和回退

- Harness 检查必须阻止依赖未验证的产品任务进入 `ready`。
- 如确需调整顺序，必须记录新的 ADR 和用户决定。
