# ADR-001：区分 Harness 状态与正式事实

- 状态：已接受
- 日期：2026-09-08

## 背景

项目需要多位 Agent 跨会话接力。把进度、架构、数据库和产品决定全部写入同一文件，会产生内容膨胀、重复和事实冲突。

## 决定

- 根目录 `AGENTS.md` 只作为入口和工作规则。
- `docs/harness/` 保存任务状态、进度、验证和交接。
- `docs/关键记录/` 保存跨模块设计、数据库、接口和 ADR。
- 产品与前后端架构继续由各自现有有效文档负责。
- Harness 通过链接进行渐进式披露，不复制完整架构内容。

## 备选方案

- 所有内容放入 `AGENTS.md`：入口过长，难以维护。
- 所有内容放入 Harness：会让执行日志成为设计事实来源。
- 只依赖聊天记录：后续 Agent 无法可靠恢复上下文。

## 影响

- Agent 必须按照规定顺序读取多个聚焦文档。
- 关键决定需要同步到正式记录，增加少量记录成本。
- 文档权威关系清楚，长期接力时更少出现冲突。

## 验证和回退

- 通过链接检查和新 Agent 接力演练验证。
- 若目录职责仍发生重复，新增 ADR 调整边界，不直接删除历史记录。
