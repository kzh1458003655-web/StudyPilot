# ADR-004：使用结构化 Commit 和模块级 PR

- 状态：已接受
- 日期：2026-09-08

## 背景

多 Agent 接力需要从 Git 历史判断每个变化的目的、范围和验证状态。模糊摘要和跨模块大提交会降低可追溯性，也难以安全回退。

## 决定

- Commit 使用 `type(scope): 中文动词 + 对象`。
- 类型限定为 `feat`、`fix`、`refactor`、`docs`、`test`、`chore`、`build`。
- `scope` 必填并使用稳定模块名。
- 一个 commit 只表达一个完整意图。
- 架构和数据库提交正文说明原因、影响、验证和回退方式。
- 一个任务或完整功能模块使用一个分支和一个 PR。
- CI 检查 Commit 格式；PR 模板要求范围、影响和证据。

## 备选方案

- 纯中文自由格式：直观但难以自动分类和检查。
- 全英文 Conventional Commits：工具兼容，但不符合当前团队的中文协作习惯。
- 单一大提交：操作简单，但难以审阅、接力和回退。

## 影响

- 提交者需要选择准确的类型和 scope。
- Git 历史可以按模块和变更类型检索。
- 不符合规范的提交会在 CI 中失败，需要修正后再合并。

## 验证和回退

- 使用合规和不合规样例测试检查脚本。
- 若规则需要扩展类型或 scope，通过新 ADR 修改，不静默放宽正则。
