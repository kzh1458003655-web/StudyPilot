# 知序课程助手模型选型实测

测试日期：2026年9月7日。工作归属：模型选型与测试模块。本记录由项目开发过程中的实际请求生成，逐题质量评分由开发助手核查，尚未经过小组成员独立复核。报告中的数据可在同目录原始文件中查证。

## 1. 选型结论

本轮建议采用 **Qwen3-4B Q4_K_M** 作为课程资料问答的候选默认模型。两款模型均完成15次请求；Qwen3在页码引用和计划JSON格式上表现更稳定，平均首token时间较短，模型文件也更小。它的通用知识解释仍有不准确之处，尤其是数据库一致性、索引维护和线程调度，不能直接把所有输出当成教材答案。

这是两款模型在15道短题上的工程选型，不能证明Qwen3在所有任务中优于Qwen3.5。Qwen3.5本轮通用知识表述更准确；如果后续主要面向无资料的知识解释，应扩大这类题目，再决定是否调整默认模型。当前选择优先考虑课程资料问答中的依据引用和结构输出。

## 2. 为什么比较这两款

现有项目已经使用Qwen3.5-4B Q4_K_M。另一款选取相近规模的Qwen3-4B Q4_K_M，避免把参数量相差很大的模型直接比较。二者都有可本地运行的GGUF文件，在本机8GB显存条件下完成了测试。

| 项目 | Qwen3.5-4B | Qwen3-4B |
|---|---|---|
| 原始模型发布方 | Qwen | Qwen |
| 本次GGUF发布方 | Unsloth | Qwen官方 |
| 量化格式 | Q4_K_M | Q4_K_M |
| 文件大小 | 2,740,937,888字节，2.553GiB | 2,497,280,256字节，2.326GiB |
| 模型许可 | Apache-2.0 | Apache-2.0 |

来源：[Qwen3.5官方模型卡](https://huggingface.co/Qwen/Qwen3.5-4B)、[Qwen3.5的GGUF发布页](https://huggingface.co/unsloth/Qwen3.5-4B-GGUF)、[Qwen3官方GGUF模型卡](https://huggingface.co/Qwen/Qwen3-4B-GGUF)。本次没有重新训练或微调模型。

Qwen3通过hf-mirror.com镜像取得Qwen官方仓库的文件；文件SHA256与下载响应中的发布值一致：`7485fe6f11af29433bc51cab58009521f205840f5b4ae3a32fa7f92e8534fdf5`。对应仓库修订号为`bc640142c66e1fdd12af0bd68f40445458f3869b`。Qwen3.5为现有本地文件，来源由项目下载脚本确认，本次计算SHA256为`00fe7986ff5f6b463e62455821146049db6f9313603938a70800d1fb69ef11a4`，没有重新与远端文件哈希核对。

## 3. 测试方法

硬件为NVIDIA GeForce RTX 4060 Laptop GPU，显存8188MiB，驱动610.62。推理程序为Windows x64版llama.cpp，build 10819，commit `6a1a922d2`。两款模型顺序运行，使用同一端口18090，避免同时占用显存。

统一参数：上下文4096、并发槽位1、GPU卸载层数99、关闭思考、temperature=0、seed=42、最大输出512 token、流式响应。每款先进行一次不计分预热，然后按相同顺序执行15题，各题只运行一次。该设置用于控制本次比较变量，并非宣称是模型的最优参数。两轮之间存在时间间隔，电脑后台负载未完全固定，速度差异仅作为参考。

题目包括：无文件通用问答5题、资料问答及证据边界6题、计划JSON3题、零学习时间边界1题。资料直接放入请求，目的是比较模型使用证据的能力，未经过PDF解析与检索模块。因此，课程隔离题只能说明模型没有臆造其他课程信息，不能代替数据库及接口层的隔离测试。

质量评分每题0—2分：2分表示满足主要内容与明确格式要求；1分表示核心答案可用，但存在局部知识错误或遗漏明确要求；0分表示结果不可直接使用，例如JSON无法解析。质量评分保存在`quality-review.json`，程序只负责汇总。三道计划题另用标准JSON解析器直接解析，不自动补括号，也不去除Markdown后再计分。

首token时间从客户端发出请求开始，到收到首个非空正文片段结束；不计仅含角色的SSE事件。平均生成速度为每题`(输出token数-1)/(总耗时-首token耗时)`后取算术平均。输出token数由服务端usage返回。不同分词器的token长度可能不同，不能只凭token/s判断模型实际回答效率。

显存每约0.5秒通过nvidia-smi采样，包含模型加载、预热、正式请求阶段，取整个GPU已用显存的最大值。该值包含Windows桌面及其他应用，不是模型独占显存，也不是理论显存下限。

## 4. 实测结果

| 指标 | Qwen3.5-4B Q4_K_M | Qwen3-4B Q4_K_M |
|---|---:|---:|
| 请求正常完成 | 15/15 | 15/15 |
| 逐题质量分 | 25/30 | 27/30 |
| JSON直接解析通过 | 2/3 | 3/3 |
| 平均首token时间 | 0.204秒 | 0.080秒 |
| 平均完整回答耗时 | 1.077秒 | 0.923秒 |
| 平均生成速度 | 52.66 token/s | 58.47 token/s |
| 设备已用显存峰值 | 2961MiB | 3137MiB |

Qwen3.5的主要问题是：三道需要页码的题目给出了正确内容，但没有标注页码；一份三天计划缺少最外层结束大括号，不能直接解析。Qwen3完成了本轮引用与JSON要求，但把数据库一致性说成“事务前后数据状态一致”，把索引维护泛化为重建，对进程与线程调度的解释也不够准确。Qwen3的一道计划每天重复相同主题，虽然满足题目格式和时间约束，但计划的实用性仍需改善。

两款模型均能在没有文件时回答通用问题；均在资料没有考试日期时说明资料未提供；也均未执行参考段落中要求把4次改成99次的干扰指令。仅一条干扰样本不能证明系统能够防御所有提示注入。

## 5. 对产品的直接改进

1. 无文件时使用通用问答提示，不应因为资料列表为空而拒绝发送请求。
2. 引用显示以检索到的真实文件及页码为准，不单靠模型自由生成引用文本。
3. 计划输出需要后端解析和字段校验，失败时明确提示重试，不能把格式错误静默保存。
4. 课程隔离必须落实到文件、检索、会话和数据库查询条件，不能仅在提示词里写课程名称。
5. 为下一轮保留同一批题目，并加入真实PDF、长对话、失败重试及更多数据库概念题；由小组成员盲评，降低开发者主观评分影响。

## 6. 复现与证据

在项目环境安装Python requests，确保18090空闲、没有另一模型同时占用GPU，依次执行：

```powershell
python .\evaluate.py --model D:\StudyPilot-runtime\Qwen3.5-4B-Q4_K_M.gguf --name Qwen3.5-4B
python .\evaluate.py --model D:\StudyPilot-runtime\Qwen3-4B-Q4_K_M.gguf --name Qwen3-4B
python .\summarize.py
```

重跑会更新对应模型目录的数据，请先备份本轮结果。评测程序只终止自己启动的模型进程。首次调试发现SSE响应未声明UTF-8时客户端可能把中文错误分行；程序已显式设置UTF-8，保留的正式结果均来自修正后的完整重跑。

各模型目录中的`metadata.json`记录模型哈希和启动命令；`results.json`保存逐题请求、正文、全部SSE事件及时间；`gpu-samples.json`保存显存采样；`server.log`保存推理日志。`results.csv`便于Excel查看，`summary.json`用于复算，`evidence.html`为依据这些数据生成的证据页面，可供浏览器截图。网页展示的是整理后的实测数据，原始依据仍是上述JSON和日志。
